技能包地图

一条主流程、三个入口、两层词汇、38 个技能的三层索引。软件工程是主线，技能包是练习场；不确定时，先用 /ask-matt。

主流程：五步

1

/grill-with-docs

访谈 + 写 GLOSSARY / ADR

2

/to-spec

综合成 spec，确认 seam

3

/to-tickets

纵向切片 + 阻塞边

4

/implement

按工单做，内部 TDD + 审查

5

/code-review

对整条分支做双轴复审

收尾：提交 → 需要时 /pr 写 PR（Pull Request，合并请求）body → /retro 改进 agent 环境。

旁路：纸上答不出的设计问题 → /prototype，用 /handoff 进出。整份 spec：不想逐张盯 → /implement-spec，子代理并行做 frontier。小工作：一次会话能做完 → 直接 /implement。

三个入口

外部输入

/triage

别人提的 issue / PR，先分类、补齐、写成 agent-ready。

不要 triage 自己产出的工单。

坏了

/diagnosing-bugs

先拿到一条会红的反馈回路，再谈原因。

修完加回归测试，再跑 /retro。

太雾

/wayfinder

一次会话装不下的大工作，先产出决策地图。

它产出决策，不产出功能；地图清了回 /to-spec。

阶段边界：五选一

选项什么时候
Continue下一阶段需要这一阶段的原文，或还有 smart zone（智能区）。
/clear上下文对下一步无关。最便宜。

工作台：两层安装

第一层，技能包（每台机器一次）：

npx skills@latest add mattpocock/skills -a opencode -g -s "*" --copy

验证：npx skills@latest ls -g；更新：npx skills@latest update -g。

第二层，仓库（每个仓库一次）：在 OpenCode 里运行 /setup-matt-pocock-skills。
