深模块参考卡

模块 = 接口 + 实现。deep module（深模块）的判据是 leverage（杠杆）：学一份小接口，换很多行为。按「什么会变」决定什么藏进实现——information hiding（信息隐藏）；并把承诺写成 invariant（不变量）：任何时刻都为真、只用公开操作就能在测试里守住。

三个概念，同一件事的三面

接口是调用者必须知道的一切，不只是签名。签名之外还有不变量、错误模式、顺序约束、配置与性能特征——任何「不写下来调用者就会猜错」的事实，都属于接口。

概念判据 / 定义反面
deep module（深模块）小接口 + 很多行为；杠杆：解决一个问题的方案顺手解很多问题（Ousterhout ch.21, p172）shallow module（浅模块）：接口和实现一样复杂
information hiding（信息隐藏）按「设计决定会怎么变」拆模块（Parnas 1972）；藏「调用者不必知道、而预期会变」的东西按流程步骤拆；或把调用者需要知道的行为也藏了（obscurity，Ousterhout ch.6, p44）
invariant（不变量）任何运行时刻都为真的性质（MIT 6.031 R11）；写在 rep 旁边，单点强制愿望式不变量：「数据要正确」——写不出断言的不是不变量

信息隐藏：什么该藏

  • 藏实现选择：文件格式、id 生成规则、匹配算法——今天调用者不必知道、明天会变的设计决定。
  • 露行为契约：匹配规则是「什么行为」不是「怎么实现」，属于接口；藏了它，调用者只能靠试，这是 obscurity 不是设计。
  • representation exposure（表示暴露）是大忌：把内部容器/引用直接给调用方，等于让他能改破不变量，也改掉了表示独立（representation independence）。

不变量的写法（MIT 6.031, Reading 11）

写什么形式沙盒例子
rep invariant（表示不变量，RI）RI : R → boolean，判定哪些内部状态合法「每个条目 id 非空且唯一」「内存条目与 kb.jsonl 的行永远一致」
abstraction function（抽象函数，AF）AF : R → A，说明内部状态对应什么抽象值「这组 JSON 行 = 一个按插入顺序的条目序列」
单点强制写在 rep 旁 + 类型 / 写入口守住 + 测试只走公开操作__post_init__ 校验、返回副本不给内部引用

ADT invariants replace preconditions：「有序无重复」不再写进每个函数的前置条件（precondition），由 SortedSet 类型在一个地方守住——不变量省掉的是每个调用点的设防。

行业做法（无统一标准，只有主流与取舍）

做法类型要点 / 产物 / 代价
接口先行（接口草图）主流实现前写签名+不变量+错误模式+示例；对着草图评审。产物：一页草图（也是第 15 课原料）。代价：必返工
deletion test（删除测试）主流想象删掉模块：复杂度消失=pass-through；复杂度在 N 个调用点重现=挣到位置。零成本，只答「该不该存在」
不变量单点强制主流RI/AF 写在 rep 旁；类型与写入口强制；不返回内部引用。代价：调试多点一层
接口即测试面主流断言只用公开操作；想越过接口测试 = 模块形状不对，记「接口缺口」
general-purpose vs special-purpose取舍Ousterhout：somewhat general-purpose（ch.6 §6.1, p40）。调用方式会变才值得通用；一个特化调用者别硬造抽象

AI + Matt：codebase-design 怎么落地

  • 模型调用的技能，设计 / 重构 / 评审接口时被 agent 拉起；词汇固定：module / interface / implementation / depth / seam / adapter / leverage / locality，不许换词。
  • 三件工具：深浅三问（方法能更少吗？参数能更简单吗？还有复杂度该藏吗？）；删除测试；接口即测试面（三条可测形状：收依赖不造依赖、返回结果不改状态、表面面积小）。
  • 人拍板三件：什么算秘密（什么藏起来）；不变量选哪条（它是承诺）；深到什么程度够（为小而小会变 obscurity）。
  • 和理论的差异：技能拒绝「实现行数/接口行数」度量深度（会奖励把实现写胖），改用 depth-as-leverage（按杠杆算深度）；Ousterhout 书里判据是「接口复杂度 vs 功能」，重心不同（经验判断：用技能的判据，直接对准调用者体验）。
  • 分工：domain-modeling 管词（GLOSSARY / ADR），codebase-design 管形状；先词后形。

逐条检查：
1. 草图覆盖调用者必须知道的一切吗？签名之外，不变量、错误模式、顺序约束有没有漏？
2. 「不必知道」清单列了什么？有没有把调用者需要知道的行为也藏了进去？
3. 这个模块是深是浅？三问过一遍。

6. add()/search() 返回内部 dict 威胁哪条不变量，草图里指出来了吗？

结论：这张草图能当合同用吗？不变量守得住吗？哪处是接口形状问题而不是测试问题？

三个容易滑进去的坑

坑表现怎么防
把接口理解成签名草图只有函数名和参数补不变量、错误模式、顺序约束——接口是「必须知道的一切」
藏得太多行为契约也被藏，接口成谜语藏实现选择、露行为契约（Ousterhout ch.6, p44）
不变量写成愿望「数据要正确」「搜索要可靠」写成可断言的句子：「id 非空且唯一」是，心情不是
