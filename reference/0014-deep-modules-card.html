深模块参考卡

模块 = 接口 + 实现。deep module（深模块）的判据是 leverage（杠杆）：掌握一份小接口，换很多行为。按「什么会变」决定什么藏进实现——information hiding（信息隐藏）；把承诺写成两层 invariant（不变量）：interface invariant（接口不变量）进草图、能用公开操作断言，rep invariant（表示不变量）写在 rep 旁的普通注释、由代码检查。

概念与两层不变量

接口是调用者必须知道的一切，不只是签名。签名之外还有接口不变量、错误模式、顺序约束、配置与性能特征——任何「不写下来调用者就会猜错」的事实，都属于接口。表示不变量不在此列。

概念判据 / 定义反面
deep module（深模块）小接口 + 很多行为。书 p172 的 leverage（杠杆）是「解决一个问题，顺手让很多别的问题也能被解决」；depth-as-leverage（一份接口换很多行为）是 codebase-design 的释义（Ousterhout 原文在 ch.4，本地摘录未收）shallow module（浅模块）：接口和实现一样复杂
information hiding（信息隐藏）按「设计决定会怎么变」拆模块（Parnas 1972）；藏「调用者不必知道、而预期会变」的设计选择按流程步骤拆；或把调用者需要知道的行为也藏了（obscurity，Ousterhout ch.6, p44）
interface invariant（接口不变量）调用者能依赖的承诺；写在草图；每个公开操作开始和结束时为真；能用公开操作断言写成愿望（「数据要正确」）；或压根不写，让调用者去猜
rep invariant（表示不变量）判定哪些内部表示合法；写成 rep 旁的普通注释（RI : R → boolean）；由代码检查（checkRep()）写成公开 docstring / Javadoc，破坏表示独立与信息隐藏
abstraction function（抽象函数）AF : R → A，说明内部状态对应什么抽象值；写在 rep 旁，只作文档，没有运行时检查当作公开规格发布；或以为它能被断言

MIT 的定义说的是程序状态；在 ADT 的读法里，不合 RI 的 rep 状态没有对应抽象值，所以工程上把检查点放在操作边界——创建、修改之后，以及测试观察的时刻。MIT 的做法是在 creators（创建者）、producers（生产者）、mutators（修改者）末尾调用 checkRep()。方法执行中的临时状态不对应任何抽象值，允许暂时不满足，只要没有外人能看见。「每个公开操作开始和结束时为真」说的就是检查点口径。

信息隐藏：什么该藏，什么该露

  • 藏实现选择：文件格式、id 的生成机制、匹配算法、索引结构——今天调用者不必知道、明天会变的设计决定。id 的语义（非空、唯一、稳定、调用者当作不透明句柄）属于接口，不属于这一类。
  • 露行为契约：匹配语义（大小写敏不敏感、搜哪些字段、结果顺序）、错误模式、顺序约束属于接口；藏了它们，调用者只能靠试，这是 obscurity 不是设计。
  • representation exposure（表示暴露）是大忌：把内部容器/引用直接给调用方，等于让他能改破表示不变量，也改掉了表示独立（representation independence）。沙盒起点里公开可写的 entries、返回内部 dict，都是实例。

不变量怎么写（MIT 6.031, Reading 11）

R 是 rep（内部表示）的取值空间，A 是抽象值的空间；RI 判定哪些内部状态合法，AF 说明这组状态对应什么抽象值。

层写在哪谁守 / 怎么验沙盒例子
interface invariant（接口不变量）interface-sketch.md 的草图调用者可见；测试用公开操作在操作边界断言；行为契约（如 search 大小写不敏感）是后置条件，不是状态不变量「每个条目 id 非空且唯一」
rep invariant（表示不变量，RI）storage.py 里 rep 旁的普通注释一处 checkRep() / 构造与写入口检查；不进公开规格「entries 里每个 dict 恰好四个键，id 非空且互不重复」
abstraction function（抽象函数，AF）同上，紧跟 RI只作文档，不强制；说明这组 dict 对应什么抽象值「这组 dict = 按插入顺序的条目序列」

ADT invariants replace preconditions：「有序无重复」不再写进每个函数的前置条件（precondition），由 SortedSet 类型在一个地方守住；此后以它为参数的函数不必重复这条。

「内存与文件一致」不是 RI：R 只是 entries，文件在对象外。这条是持久化一致性，靠集成测试或 adapter 契约测试管。

行业做法（无统一标准，只有主流与取舍）

做法类型 / 来源要点 / 产物 / 代价
接口先行（接口草图）主流 / CMU 17-313《08-design-docs》「Code review before there is code!」实现前写签名+接口不变量+错误模式+顺序约束+调用示例，对着草图评审。产物：一页草图（第 15 课原料）。代价：必返工
deletion test（删除测试）常用启发式 / codebase-design 原则想象删掉模块：复杂度消失=pass-through；复杂度在多个调用点重现=挣到位置。零成本，只答「该不该存在」
不变量单点强制主流 / MIT 6.031 checkRep() 与「普通注释」RI 写 rep 旁、由 checkRep() 检查；AF 只作文档；构造与写入口检查；不返回内部引用。代价：调试多点一层
接口即测试面主流启发式 / codebase-design（probably the wrong shape）断言只用公开操作；想越过接口测试 = 多半形状不对，记「接口缺口」；合法的内部接缝不算错
general-purpose vs special-purpose取舍 / Ousterhout ch.6 §6.1, p40somewhat general-purpose：调用方式会变才值得通用；一个特化调用者别硬造抽象

AI + Matt：codebase-design 怎么落地

  • 模型调用的技能，设计 / 重构 / 评审接口时被 agent 拉起；词汇固定：module / interface / implementation / depth / seam / adapter / leverage / locality，不许换词。
  • 三件工具：深浅三问（方法能更少吗？参数能更简单吗？还有复杂度该藏吗？）；删除测试；接口即测试面（三条可测形状：收依赖不造依赖、返回结果不改状态、表面面积小）。
  • 技能产什么：一份接口方案（签名、接口不变量、错误模式、调用示例），技能没有规定固定文件格式；课件里的「草图」是本课给这份产物起的名字，落点是 .scratch/storage-module/interface-sketch.md。
  • 人拍板三件：什么算秘密（什么藏起来）；接口不变量选哪条（它是承诺）；深到什么程度够（为小而小会变 obscurity）。
  • 和理论的差异：技能把「实现行数/接口行数」列为 Ousterhout 的 rejected framing 并明确拒绝（会奖励把实现写胖），改用 depth-as-leverage（按杠杆算深度）。书里的 depth 定义在 ch.4，本地摘录不含 ch.4，读书按原著读 ch.4。
  • 分工：domain-modeling 管词和决定（GLOSSARY.md 管名字与定义，ADR（架构决策记录）管难回滚的取舍，第 4、7 课）；codebase-design 管形状；先词后形。

三个容易滑进去的坑

坑表现怎么防
把接口理解成签名草图只有函数名和参数补接口不变量、错误模式、顺序约束——接口是「必须知道的一切」
藏得太多行为契约也被藏，接口成谜语藏实现选择与算法、露行为契约（Ousterhout ch.6, p44）
不变量写错层或写成愿望「数据要正确」；或把「每个 dict 恰好四个键」写进公开草图接口不变量进草图、公开断言；表示不变量写 rep 旁普通注释、由代码检查；两层各有读者
