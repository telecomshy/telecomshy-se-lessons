过程模型参考卡

spec 就绪不等于「知道怎么开工」。过程模型在回答「怎么把工作排开」，本质是你对「需求何时敢提前写死」的预判。没有普适最佳，只有按项目画像在「预测式 → 自适应式」连续谱上挑一个落点。

位置：它属于哪个活动

活动过程在这里做什么
Process & Management（过程与管理）模块二的导读：第 8 课 spec 就绪后，回答「用什么样的过程把它排出来」。给第 10 课 to-tickets、第 11 课估算定位。
SWEBOK 支点「没有理想过程存在，只能挑选和适配」（ch.10 p10-2）；过程是一条 predictive → adaptive 的连续谱（ch.9 p9-8）。

核心概念：过程在回答什么

过程模型（process model）= 你怎么把工作排开。选择它，本质是回答「需求此刻有多可确定」——这就是预测式与自适应式的分歧。

谱系：predictive → adaptive

端点特征
预测式 predictive开工前写死需求和架构、尽量少迭代；一次计划成本最低。
自适应式 adaptive接受需求会变、小步迭代、频繁调计划；靠反馈兜底。
中间预设日程产出增量（偏预测式）或频繁更新的小周期产出增量（偏自适应式）。

三种过程：各怕什么

过程怎么做适合代价
瀑布式 waterfall（顺序式）需求 → 设计 → 实现 → 测试一条直线，只向前走，需求定下后基本不改（SE-EDU Sequential）。需求一开始就被理解清楚、要按合同交付需求在开工后才变 → 一次性计划全部作废
迭代式 iterative多轮迭代，每圈走全程、产新版本、反馈进下一圈；广度优先每圈有可用产品 / 深度优先每圈厚实一部分需求会变、要多早拿到反馈计划要随反馈反复调整，得有反馈回路
敏捷 agile（Scrum / XP）需求按价值进 product backlog；Sprint（冲刺）内需求冻结；结束时演示 + 复盘；依赖持续客户协作需求频繁变化、要快速交付拿反馈高度依赖客户参与和团队自律，否则塌空

没有标准答案：选型的四个变量

SWEBOK：没有理想过程，只有对项目和上下文的挑选、适配。选型看四件事：需求多稳、风险多高、多早要反馈、团队 / 客户能不能持续参与。

别把任何过程当「最佳实践」。过程不是教条，是一个你按项目画的取舍。

本课程自己这套流程站在哪

  • 链路：grill → to-spec → to-tickets → implement → code-review（第 3 课五步）＝一套完整过程。
  • 偏预测式：先 spec 再动手、每张工单带验收、一次只做一件事。
  • 偏自适应式：拆得小、每张可独立验收、有反馈回路、没写死的需求靠下一张工单补。
  • 为什么是中间路：单人 + agent，没有团队沟通成本、没有合同化交付压力，不必为它们买单。
  • 提醒：别把本课中间路当新教条；真实项目要按画像往谱两端选。

练习怎么验

读我这份「什么项目适合什么过程」的对照表，再读
SWEBOK 第 9、10 章、SE-EDU Process Models。

逐条检查：
1. 我选的模型，跟「需求稳不稳、反馈快不快」对上了吗？
2. 有没有把某过程当绝对最佳？有没有写下「这个项目为什么」？
3. 我在 predictive / adaptive 谱上的定位跟理由一致吗？
4. 备注里标出「明天要交货」这类变量会让选型怎么变了吗？

最后给结论：现在选型和理由还成立吗？哪里站不住？

三个容易滑进去的坑

坑表现怎么防
把过程当教条「敏捷就是对的」「瀑布过时了」每次都说清「这个项目为什么」，不写「一般最好」
忘了先想需求稳不稳上来就选，不画项目画像先写需求多稳、反馈多快，再落到谱上
把本课流程当新模板真实项目也照搬「先 spec 再小步」记住选型的变量，按画像选，别照搬
