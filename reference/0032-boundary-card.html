位置：它属于哪个活动

活动阶段边界在这里做什么
跨活动，落在专业实践阶段边界不占第九个活动：它不产出需求、代码、测试，只决定「干活的那个上下文怎么换」。第 30 课答「下一步不清楚」，第 31 课答「手上没有事实」，本课答「上下文装不下、也不该继续装」。
输入从哪来第 31 课研究笔记的「还没答」节、第 30 课 verdict.md 留的问题（没做则跳过）、.scratch/incident-2901/issues/ 的工单状态——合起来是「这个会话还挂着什么」的清单。
给下一课的起点一份边界决策记录 decision.md，加一份落在 %TEMP% 的交接文档。第 33 课接着答「哪些事不能交给 AI、哪些输出必须人验证」。

概念：smart zone、阶段边界、一手与二手的上下文

smart zone（智能区）：会话开头 agent 锐利，变长后滑进 dumb zone（迟钝区）——更糙、更忘事、错得更自信，即 attention degradation（注意力退化）。前沿模型通常在 125K–150K token 开始（作者标 “though this is debated”）。「The zones don't track the context window limit」——窗口上限是工具拒绝继续的地方，质量早就开始掉。上下文是预算，不是仓库。stateless（无状态）：模型不记得旧会话，新会话从零开始，需要的东西必须显式携带。phase / phase boundary（阶段 / 阶段边界）：阶段是会话里的一段活，「心里冒出『行，这块完了』」就结束；边界是两段活之间的空隙，这个决定唯一该待的地方——中途只有继续或拆子代理，中途压缩会丢了线头。一手 / 二手的上下文：会话原文是一手来源，摘要与交接文档是二手（Full / Lots / Little 对 Lossy / Less / Lots），所以第一问永远是「能不能继续」。

行业做法：四条，前三条练习直接用

做法怎么做产物与代价
一次会话一件事每个会话认领一个能收口的目标，做完就停，下一件事换新会话。AI Hero：「Doing one task per session gives each task the sharpest part of the session.」呼应第 12 课 wayfinder「一次 session 最多解一张 ticket」。产物：一个会话一个结论。代价：多开几次会话，交接要写得更认真。
交接要有产物 + 明确确认SRE：「A handoff process maintains shared state between ticket handlers as responsibility switches over.」「Formalize the handover process」；事故交接要等到「firm acknowledgment of handoff」。产物：交接文档 + 接手方复述「我接的是什么、下一步做什么」。只有文件没有确认，交接没完成。
交接文档写给零上下文的读者失败信号是 relitigation（翻案）：只记了决定了什么、没记为什么；判据「用一个零上下文的会话拿着它能做什么」。CMU p66：「Explicit context/documentation is MUCH better than implicit documentation。」产物：每条决定跟一句理由、每个产物给路径。代价：写的时候多几行，换来接手的人不重开旧议题。
交接有成本，取舍（SWEBOK ch.7 §2.2.5）「a handoff process must be put in place between developers and maintainers, which sometimes leads to friction between teams」。落点是有没有东西要移动：不跨工具、不跨目录或仓库、不跨人、不分叉，就别交。产物：一次「继续 / 压缩」的便宜决定。代价：交早了白写，交晚了上下文已经烂掉。

AI + Matt：五问判断树 + handoff 技能

判断树（ask-matt 的 Phase boundaries / PHASE-BOUNDARIES.md，第一个 yes 赢）：① 能在当前会话继续吗——下一阶段要这一阶段的原文，或剩下的 smart zone 够用（技能文档给的量级约 15 万 token；继续不花钱，先排除）；② 上下文对接下来的事无关吗——是则 /clear，代价单向（丢掉「为什么」）；③ 需要交棒吗——只在换工具 / 换目录 / 交给同事 / 中途分叉四种情况，买的是可携带性；④ 能 AFK 做完吗——是则派 subagent，报告回来；⑤ 否则才 /compact，并给它一句指令让摘要留下一阶段要的。压缩是默认，不是第一反应——从它开始的失败是「新会话对被摘要抹平的决定自信地理解错」。
与第 18 课 design doc 的分工：handoff 是会话级、存临时目录、活不过一次会话；design doc 是作品级、进仓库、跟功能走；换会话开工时前者管开局、后者管长期，要长期留的决定与判据落回仓库。
handoff 技能（用户调用，disable-model-invocation: true）：六条——压成交接文档；存操作系统临时目录（Windows %TEMP%）不存工作区；含 “suggested skills” 一节点名下个会话该调的技能；引用不复制（spec / 计划 / ADR / issue / 提交 / diff 只给路径或 URL）；脱敏；参数当作下一会话的焦点。
OpenCode 对应动作：清空 = 开新会话 /new（Ctrl+X 再 N，旧会话保留）；压缩 = session.compact（Ctrl+X 再 C）加默认开启的自动压缩（保留最近约 15000 token），且是原地替换、不开新会话；交棒 = 同一个技能，写 @handoff …… 或用技能选择器加载；子代理 = 新上下文的子会话（内置 general / explore）。
人拍板四件：是不是真的到了边界；下一阶段要不要原文；交接文档带什么（引用 vs 写死、脱敏）；哪块能 AFK、报告拿什么验收。生效判据：零上下文的会话不追问就能接着走。

三个容易滑进去的坑

没到边界就动手——干到一半压缩，然后花十轮把说清的事再说一遍；只在「行，这块完了」那一刻做决定。一满就压缩——跳过前四个更便宜也更准的问题，最贵的漏判是「下一阶段需要原文却只给了摘要」。交接只记决定了什么——流水账没有理由，新会话会把定过的决定翻出来重议；每条决定跟一句理由，能给路径的给路径，敏感信息先脱敏。

练习怎么验

清单覆盖第 31 课「还没答」的每条缺口加工单状态；每条挂账指得出第一个 yes 落在哪一问，理由指得回清单的行；五问没有跳序；clear 与 compact 各至少一处判断且没真按；handoff 真跑过、四条核对全过、路径在 decision.md 里；第一行是一句带条件的决定。反馈回路里 agent 扮演零上下文接手方，按八条核（能不能说出下一步与依据、顺序有没有跳、决定有没有为什么、有没有复制与敏感信息、suggested skills 匹配吗、清单漏没漏）。读反馈归位四类：接不上→补交接文档重跑 handoff；顺序或按法错→按五问重走改记录；清单漏→先补进 open-items.md 再决定归哪段活；单条没对上（suggested skills 不匹配、决定缺为什么）→回对应步骤局部补。
