wayfinder 参考卡

当项目大到、模糊到连工单都拆不出来时，别急着更细地估算，先把雾变成图：一张 issue tracker 上的「决策地图」，每个 ticket 是一道待解的决定（不是一段待做的活），一次解一张，直到通往目的地的路清晰。判据是「现在能不能把问题说尖」，不是「现在能不能回答」；扫完没有雾，就别建图。

位置：它属于哪个活动

活动wayfinder 在这里做什么
Process & Management（过程与管理）模块 2 第四站（倒数第二站）：第 10 课拆工单、第 11 课估算都假设「能开工」；本课处理「大到、模糊到连工单都拆不出来」的项目，把雾变成决策地图。第 13 课 triage 处理「别人递进来的外部问题」。
SWEBOK 定位自适应式：需求不稳时不宜一次排满，用总体估算 + 逐迭代调整、约束反推迭代数（ch.9 p9-9）。
SE-EDU 定位Milestones：不现实为整个项目做详细计划，用高层计划 + 近几个里程碑详设。

何时该用 / 何时不该用

情况判定
用 wayfinder太大 / 太模糊，一个 session 装不完，「拆」本身都要先定一个决定；从「这里」到「那里」怎么走需要先解决一堆决定。
不用 wayfindergrill 广度优先扫完「没有雾」——旅程小到、清楚到一个 session 能装完，能直接开工 / 直接拆工单。建图是额外负担。

判据核心：雾不雾，看「现在能不能把问题说尖」，不是「现在能不能回答」。能说清 → 建 ticket；还说不清 → 留在 Not yet specified。

地图（index 不是 store）

地图 = tracker 上打 wayfinder:map 标签的单一 issue；索引（index），不是存储（store）：每个决定只住在它自己的 ticket，地图只写一行摘要（gist）+ 链接，不重复全貌。

  • Destination（目的地）：先命名，塑造后面每张 ticket；可能是 spec / 锁定的决定 / 原地改动（迁移）。
  • Notes：领域、每次 session 要 consult 的技能、本 effort 的固定偏好。
  • Decisions so far：每张已关 ticket 一行「摘要 + 链接」的索引。
  • Not yet specified：还在雾里、现在说尖不了的部分（可写松写全，随 frontier 推进逐块毕业）。
  • Out of scope：被目的地排除的工作——不是雾，永不毕业；只有目的地重画，才可能以新 effort 回来。

铁律：Plan, don't do

地图产决定，不产交付物。每张 ticket 解决一道决定，不是做一段活；地图「完成」= 路清晰、开工前无遗留待定项，不是功能做完。「想直接开做」的冲动 = 到了地图边缘、该交接了。effort 可在 Notes 改写此默认，但默认先解决定。

四种 ticket 类型

类型HITL / AFK解什么怎么做
researchAFK查事实：文档、第三方 API、知识库子 agent 调 "research" 技能（回指第 31 课）
prototypeHITL「它长这样/那样」——用廉价粗糙产物加高讨论保真调 "prototype" 技能，产物链到 issue（回指第 30 课）
grillingHITL对话，默认类型同时调 "grilling" + "domain-modeling"（回指第 5、4 课）
taskHITL 或 AFK为决定扫障的手工活（注册服务、移数据看形状）唯一「做活」的类型，但为解锁决定服务，非为到达目的地

HITL（human in the loop，人机回环） = 必须真人亲自说话、代表自己才能解；agent 绝不能替人回答。AFK（away from keyboard，无人值守） = agent 独立解。

AI + Matt：wayfinder 怎么落地

  • 用户调用（disable-model-invocation: true）；前置：tracker 已 setup。为什么是用户调用：要不要建图先由你拍板。
  • 建图 chart the map：命名目的地（grilling + domain-modeling）→ 广度优先 grill 摸前沿 → 无雾则停 → 建地图 → 建可指定 ticket → 第二遍连阻塞边（需要 id）→ research 子代理并行查 → 停（建图不解题）。
  • 走图 work through the map：load 高层图 → 认领 frontier 第一张（先 assign，再干活）→ 按 wayfinder:<type> 解 → resolution 评论 + 关 issue + 地图追加一行 → 毕业新雾 / 清 Not yet specified / 越界关 out of scope。
  • 一次 session 最多解一张 ticket（research 例外）。

练习怎么验

读我这份「多来源知识库」的纸面决策地图（目的地 / Not yet specified / 我挑的 ticket / 是否该用 wayfinder），
再读 C:\Users\admin\.agents\skills\wayfinder\SKILL.md。

逐条检查：
1. Destination 是一句「走到什么」的具体描述，不是口号？
2. Not yet specified 各项是「说尖不了的雾」，还是已经能建 ticket？
3. ticket 的 type（grilling/prototype/research/task）与 HITL/AFK 标对了吗？
4. 有没有把「决定」写成「待做交付物」？
5. Out of scope 和 Not yet specified 分开、没有混着？
6. 守了 Plan, don't do 吗？没滑到「顺便把活做了」？

最后给结论：雾和 ticket 分得清吗？继续建图，还是直接走 spec → tickets？

坑表现怎么防
