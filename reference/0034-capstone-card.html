综合演练与迁移参考卡

流程靠裁剪搬进新仓库：先在熟悉的地方走通整条链，再按新仓库的差异特征决定留什么、舍什么、先搬哪一站。第一张工单就是流程的追踪弹；迁移计划写给零上下文的读者。

概念：演练、裁剪、可重复的发布

drill（演练）：一个真的功能从需求走到上线，每一站都真的调技能、真的落产物。练习回答「单个活动怎么做才好」，演练回答「活动之间接不接得上」。第 29 课的演练对象是事故，本课的演练对象是流程。
adaptation（裁剪）：SWEBOK ch.10 §2.8（printed 10-8）的四步——识别差异特征、挑标准与文档、选策略/阶段/过程、记录决定与理由；「The adaptation will not require keeping the names provided in Section 2, or including them all」：允许留、舍、换名字，条件是四步都走了、理由都写了。同章 §1.1（printed 10-2）：「no ideal process, or set of processes exists…」（第 9 课已引，尺度换成整个流程）。
release（发布）：SWEBOK ch.8 §6（printed 8-13）：「distributing software and related artifacts outside the development activity, including internal releases and distribution to customers」——内部发布也算发布。SRE《Release Engineering》的要求：发布可重复、「aren't 'unique snowflakes.'」、对流程的改动「intentional, rather than accidental」。

需求站的六个问题（示例答案，不是标准答案）

问题推荐答案（示例）
暴露哪些操作？POST /add 与 GET /search?q=；不做 delete——Store 契约里没有它。
错误怎么映射？缺字段 400；内部失败 500 通用消息加关联编号，详情进 stderr（第 33 课取舍，复查条件在本课触发）。
监听地址？只监听 127.0.0.1（最小权限）。
q 为空、大小写、匹配语义？沿用 Store 契约；第 19 课没拍过的在这一站拍掉。
并发？单线程 server 够用；要并发先改 Store 或加锁，另开工单。
用什么库？标准库 http.server，不引入新依赖；knowledge-pet 用 FastAPI 是它自己的决策。

迁移计划：六节骨架

节写什么原料
1 现状与目标knowledge-pet 已有/没有的东西，逐条给路径；目标一句话：第一张真工单起，八站跑起来差异盘点表、docs/research/
2 迁移范围与非目标词表文件名拍板（CONTEXT.md → GLOSSARY.md 或保留）、第一张工单走完整链、测试与 CI 随第一张进；非目标：不搬沙盒代码、不重写已定决策、不动产品架构盘点表、docs/architecture.md
3 按活动的迁移顺序测试与 CI 通常前置（沙盒卡点立据）；已在用的不动；实现站从 /implement 接 spec #11 的第一张工单开始八站表、notes.md
4 交 agent / 人做 / 必须验第 33 课委托清单打底，加特有行：API Key 人输值、.env 进 .gitignore、占位符；两套语言检查进验收；SSE 先替身后真件delegation-ledger.md（或卡 0033 样例）
5 风险与回滚差异 → 风险 → 对策；gh 命令人确认后跑；密钥通道留给人；集成测试先替身后真件；每步单独提交、能单独撤盘点表第三列、第 33 课三问
6 验收与时间盒第一张工单上线后八站产物齐全可查；第一个时间盒只搬前几站，/retro 后再决定生效判据两条

差异盘点七个维度：tracker（本地 Markdown ↔ GitHub issues）、词表（GLOSSARY.md ↔ 旧版 CONTEXT.md）、代码（有 ↔ 无）、测试与 CI（无/演练后有 ↔ 无）、密钥（无 ↔ 云端 API Key）、进程形态（单进程 CLI ↔ Tauri 壳 + Python sidecar）、已有工件（练习产物 ↔ wayfinder 决策、spec #11、工单 #12–#18、prototype/ipc-shape）。每行必须填出「对流程的影响」。

生效判据

对演练：八站产物齐全可查——spec、工单、分支上的实现提交、全量测试绿、检查绿、两轴报告带裁决、README 发布说明，每样都能打开、指得到提交；反馈回路两轮有记录。
对迁移计划：借第 32 课 handoff 判据「Judge a handoff by what a session with zero context could do with it.」——零上下文的新会话拿着它，不追问就能说出第一张工单是什么、自己能做哪几步、哪几步要等人。写法纪律：引用路径不复制（第 18 课）、决定带理由（第 32 课 relitigation 判据）、写给零上下文读者。
提交：站 3 先提交 GLOSSARY.md 与 .scratch/http-adapter（记固定点）；反馈回路后 git add README.md 发布说明一笔 + git tag v0.1.0（可选）、git add .scratch/http-adapter .scratch/migration-3401 记录一笔；最后 git status 干净。

三个容易滑进去的坑

把流程当清单抄进新仓库：差异特征没识别就照单全收，搬过去一半用不上、一半缺着；每节先写仓库特征，再写留舍。把演练做成补课大扫除：缺的记进 notes.md 进迁移计划，补课回各课参考卡单独补，别挤在演练里。把迁移计划写成产品计划：功能与架构是 docs/architecture.md 的事；计划管流程落点，出现功能清单段落就删，换路径引用。
